# 2026-11-24 : écran, quatre modules ensemble et début de la carte KiCad

**Séance :** planifiée · **Durée :** 1 h 30
**Présents :** Timothé Froumentin, Victor Fonte Nove Lamotte

## Fait

- **Broches de la XIAO soudées** : c'était la cause du montage qui ne marchait qu'à moitié à la séance précédente.
- **Étape 6, l'écran** : l'écran TFT affiche le dessin de test, mais avec les **couleurs inversées** (fond clair au lieu de noir).
- **Étape 7, les quatre modules ensemble** : un point se déplace sur l'écran avec le joystick, et chaque appui sur le bouton fait un bip. **Tous les modules fonctionnent ensemble sur la breadboard** (checkpoint du TD2).
- **KiCad** : création du projet `MicroControleurs`, ajout de la bibliothèque du Makerspace au projet, et placement des premiers composants dans le schéma.

## Comment ça marche

### L'écran TFT et le bus SPI

L'écran (contrôleur **ST7789**, 240 × 320 pixels) reçoit l'image par un **bus SPI**, une liaison série rapide :

| Signal | Broche XIAO | Rôle |
|---|---|---|
| `SCK` (marqué SCL) | D9 | horloge : à chaque impulsion, un bit est transmis |
| `MOSI` (marqué SDA) | D10 | les données, de la carte vers l'écran |
| `DC` | D8 | dit à l'écran si l'octet reçu est une **commande** ou une **donnée** (pixel) |
| `RESET` | D7 | redémarre l'écran au lancement |
| `CS` | GND | « écran sélectionné » : relié à la masse, il est toujours actif |
| `LED` | 3V3 | rétroéclairage, toujours allumé |

Il n'y a pas de fil retour (`MISO`) : l'écran ne renvoie rien à la carte. Comme `CS` est fixé à GND, l'écran doit être piloté en **mode SPI 3**.

La bibliothèque **Adafruit ST7789** (avec Adafruit GFX) fait tout le travail bas niveau : on lui demande « écris PONG », « dessine un rectangle », et elle envoie les bons octets.

### Les couleurs inversées

Le ST7789 a une commande « inversion des couleurs » : selon le modèle de dalle, il faut l'activer ou non pour avoir les vraies couleurs. Sur notre écran, la configuration par défaut de la bibliothèque donne l'inverse : le noir apparaît clair, le blanc apparaît sombre. Le câblage et le code sont bons, c'est un simple réglage de l'écran.

### Le programme des quatre modules (étape 7)

Il réunit tout ce qu'on a fait au TD2 :

- **Boucle de jeu à environ 60 images par seconde** : `loop()` ne fait une mise à jour que toutes les **16 ms**, mesurées avec `millis()`, sans `delay()`. Rien ne bloque, donc le joystick, le bouton et l'écran sont tous lus et mis à jour à chaque image.
- **Joystick** : la valeur normalisée de -1 à +1 (étape 4) fait avancer le point de `x × 4` pixels par image, borné entre 0 et 235 pour rester dans l'écran.
- **Bouton** : `justPressed()` (étape 2) détecte un appui et lance un **bip de 50 ms** avec `tone()`. `tone()` ne bloque pas, donc le point continue de bouger pendant le bip.
- **Affichage sans traînée** : au lieu de redessiner tout l'écran (trop lent), on efface seulement l'**ancien carré** de 5 × 5 pixels et on dessine le **nouveau**, et seulement si la position a changé.

### Les bibliothèques KiCad

Dans KiCad, chaque composant a deux représentations :

- un **symbole**, son dessin dans le **schéma** (fichier `.kicad_sym`) ;
- une **empreinte**, la forme de ses pastilles de cuivre sur le **circuit imprimé** (dossier `.pretty`).

La bibliothèque du Makerspace contient les composants disponibles au Makerspace. On l'ajoute **au projet** plutôt qu'à l'installation de KiCad : le projet reste complet et s'ouvre sur n'importe quel ordinateur.

## Comment on a fait

### 1. Souder les broches de la XIAO

Barrettes enfoncées dans la breadboard pour les tenir droites, XIAO posée dessus, puis une soudure par broche. Vérification : chaque soudure est brillante et en forme de cône, sans pont d'étain entre deux broches voisines.

### 2. Câbler l'écran (carte débranchée)

| Broche de l'écran | XIAO |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SCL (SCK) | D9 |
| SDA (MOSI) | D10 |
| RES (RESET) | D7 |
| DC | D8 |
| CS | GND |
| LED | 3V3 |

Comme plusieurs broches vont sur 3V3 et sur GND, on a utilisé les **rails d'alimentation** de la breadboard du LabDeck : un fil 3V3 → rail **+**, un fil GND → rail **–**, puis tous les modules se branchent sur les rails.

Rappel sur la breadboard : les 5 trous d'une même colonne (a à e, ou f à j) sont reliés entre eux, la rainure centrale coupe la liaison, et les rails + et – sont reliés sur toute la longueur.

### 3. Ajouter la bibliothèque de l'écran

Dans `platformio.ini` :

```ini
lib_deps =
    adafruit/Adafruit ST7735 and ST7789 Library@^1.11.0
```

PlatformIO la télécharge automatiquement à la compilation suivante.

### 4. Programme de test de l'écran (étape 6)

```cpp
#include <SPI.h>
#include <Adafruit_GFX.h>
#include <Adafruit_ST7789.h>
#include "config.h"

Adafruit_ST7789 tft(&SPI, PIN_TFT_CS, PIN_TFT_DC, PIN_TFT_RESET);

void setup() {
  SPI.begin(PIN_TFT_SCK, -1, PIN_TFT_MOSI, PIN_TFT_CS);  // pas de MISO
  tft.init(240, 320, SPI_MODE3);    // mode 3 car CS est relié à GND
  tft.setRotation(2);               // portrait, origine en haut à gauche
  tft.fillScreen(ST77XX_BLACK);

  tft.setTextColor(ST77XX_WHITE);
  tft.setTextSize(4);
  tft.setCursor(72, 40);
  tft.print("PONG");

  tft.drawRect(20, 120, 200, 60, ST77XX_WHITE);
  tft.fillCircle(120, 250, 20, ST77XX_YELLOW);
}

void loop() {}
```

**Attendu :** « PONG », un rectangle et un disque jaune sur fond noir.
**Obtenu :** le dessin est bien là, mais avec les couleurs inversées (voir *Reste à faire*).

### 5. Les quatre modules ensemble (étape 7)

Le principe de la boucle :

```cpp
void loop() {
  static unsigned long lastFrame = 0;
  if (millis() - lastFrame < 16) return;      // une image toutes les 16 ms
  lastFrame = millis();

  float x = normalizeJoystick(analogRead(PIN_JOYSTICK_X), joystickCenterX);

  if (justPressed(button)) {
    tone(PIN_BUZZER, 880, 50);                // bip de 50 ms, non bloquant
  }

  float newX = constrain(dotX + x * 4, 0, 235);
  if ((int)newX != (int)dotX) {               // redessine seulement si ça bouge
    tft.fillRect((int)dotX, 160, 5, 5, ST77XX_BLACK);   // efface l'ancien
    tft.fillRect((int)newX, 160, 5, 5, ST77XX_WHITE);   // dessine le nouveau
  }
  dotX = newX;
}
```

**Test :** le point suit le joystick vers la gauche et la droite, sans laisser de traînée ; chaque appui sur le bouton fait un bip, sans ralentir le point. On garde ce programme : il servira à **tester la carte soudée** au TD4.

### 6. Créer le projet KiCad et ajouter la bibliothèque

1. Dans KiCad : **Fichier → Nouveau projet** → `MicroControleurs`.
2. Bibliothèque du Makerspace téléchargée depuis [github.com/Makerspace-Amiens/kicad-library](https://github.com/Makerspace-Amiens/kicad-library) dans le dossier `kicad-library`, à côté du projet.
3. Ajout **au projet** (et non à toute l'installation de KiCad) :

   | Nom dans KiCad | Type | Fichier |
   |---|---|---|
   | `Makerspace-Amiens` | symboles | `kicad-library/symbol/makerspace-unilasalle.kicad_sym` |
   | `Makerspace-XIAO` | symboles | `kicad-library/symbol/XIAO-ESP32-S3-SMD.kicad_sym` |
   | `Makerspace-Joystick` | symboles | `kicad-library/symbol/Joystick.kicad_sym` |
   | `Makerspace-Amiens` | empreintes | `kicad-library/footprint/makerspace.pretty` |

   Les chemins commencent par `${KIPRJMOD}` (le dossier du projet) : le projet fonctionne tant que `kicad-library` reste à côté du fichier `.kicad_pro`.

4. Vérification : dans le schéma, touche **A**, recherche `Makerspace` : les composants de la bibliothèque apparaissent.

### 7. Placer les composants dans le schéma

| Référence | Composant | Symbole |
|---|---|---|
| U1 | XIAO ESP32-S3 | `Makerspace-XIAO:XIAO-ESP32-S3-SMD` |
| J1 | connecteur de l'écran (1 × 14) | `Makerspace-Amiens:Conn_01x14` |
| J2 | connecteur I2C (1 × 4) | `Makerspace-Amiens:Conn_01x04` |
| JOY1 | joystick | `Makerspace-Joystick:Joystick` |
| SW1, SW2 | boutons gauche et droite | `Makerspace-Amiens:SW_Push` |
| R1, R2 | résistances de tirage I2C | `Makerspace-Amiens:R` |
| R3 | résistance de la LED | `Makerspace-Amiens:R` |
| D1 | LED | `Makerspace-Amiens:LED` |
| C1 | condensateur de découplage | `Makerspace-Amiens:C` |

Le brochage à respecter (identique à la breadboard, pour garder le même code) :

| Broches XIAO | Rôle |
|---|---|
| D0, D1, D2 | joystick X, Y, appui |
| D3, D4 | I2C SDA, SCL |
| D5, D6 | SW1 (gauche), SW2 (droite), vers GND |
| D7 à D10 | écran RESET, DC, SCK, MOSI |

## Pourquoi

- **Souder avant de continuer** : sans soudure, les contacts étaient intermittents, et l'écran, qui reçoit beaucoup de données très vite, était le premier à mal fonctionner.
- **Rails d'alimentation** : un seul fil 3V3 et un seul fil GND depuis la XIAO, au lieu de multiplier les fils sur les mêmes broches.
- **Pas de `delay()` dans la boucle de l'étape 7** : avec un `delay()`, le point se figerait pendant chaque bip ; avec `millis()` et `tone()`, tout continue en même temps. C'est la structure qu'on reprendra pour le jeu.
- **N'effacer que l'ancien carré** : redessiner tout l'écran 60 fois par seconde serait trop lent par le SPI et ferait clignoter l'image.
- **Bibliothèque ajoutée au projet** : le projet reste autonome, Victor peut l'ouvrir sur son ordinateur sans rien installer.
- **Mêmes broches que sur la breadboard** : le code du TD2 fonctionnera tel quel sur la carte soudée.
- **Références SW1 / SW2 pour les boutons, JOY1 pour le joystick** : KiCad réserve la lettre **D** aux diodes et LED (D1 est notre LED), et le cahier des charges nomme les boutons SW1 et SW2.
