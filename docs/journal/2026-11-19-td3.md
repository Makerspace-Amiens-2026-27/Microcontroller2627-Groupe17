## Fait

- **Étape 5** : module buzzer câblé sur D3 et testé.
- Notre module est un **buzzer actif** : il fait un simple clic pendant le test de la gamme (test 1), puis sonne pendant une demi-seconde quand on met la broche à `HIGH` (test 2).
- Tout a fonctionné du premier coup.

## Comment ça marche

### Buzzer actif ou passif

| | Buzzer **actif** | Buzzer **passif** |
|---|---|---|
| Intérieur | contient son propre oscillateur | simple petit haut-parleur |
| Ce qu'il faut lui envoyer | un niveau fixe : `HIGH` = son, `LOW` = silence | un signal carré à la fréquence de la note (PWM) |
| Fonction Arduino | `digitalWrite()` | `tone()` |
| Hauteur du son | toujours la même | réglable (une note par fréquence) |

C'est pour ça qu'un buzzer actif ne fait qu'un **clic** avec `tone()` : il ne sait pas changer de note, il réagit juste aux changements de niveau.

### `digitalWrite()` et `tone()`

- `digitalWrite(PIN_BUZZER, HIGH)` met la broche à 3,3 V et la laisse là. Pour un buzzer actif, c'est suffisant : son oscillateur interne produit le son.
- `tone(PIN_BUZZER, fréquence, durée)` fabrique un **signal carré** à la fréquence demandée (262 Hz = do, 294 Hz = ré…), pendant la durée donnée en millisecondes. Il fonctionne en arrière-plan, sans bloquer le reste du programme.

### La broche D3

`include/config.h` contient `PIN_BUZZER = D3`, marqué « seulement sur breadboard ». Sur la carte de la console, D3 sert au connecteur I2C : le buzzer changera donc de broche sur la carte finale.

## Comment on a fait

### Câblage (carte débranchée)

| Module buzzer | XIAO |
|---|---|
| VCC | 3V3 |
| GND | GND |
| S (signal, ou `I/O`) | D3 |

⚠️ Toujours **3V3**, jamais 5V.

### Programme de test (`src/main.cpp`)

```cpp
#include <Arduino.h>
#include "config.h"   // PIN_BUZZER = D3

void setup() {
  pinMode(PIN_BUZZER, OUTPUT);

  // Test 1 : gamme do-ré-mi-fa-sol (pour un buzzer passif)
  int notes[] = {262, 294, 330, 349, 392};   // fréquences en Hz
  for (int note : notes) {
    tone(PIN_BUZZER, note, 200);   // joue la note 200 ms
    delay(250);
  }

  delay(1000);

  // Test 2 : niveau fixe (pour un buzzer actif)
  digitalWrite(PIN_BUZZER, HIGH);  // son
  delay(500);
  digitalWrite(PIN_BUZZER, LOW);   // silence
}

void loop() {
  // vide : le test ne s'exécute qu'une fois
}
```

### Test

1. Upload, puis écouter.
2. **Test 1** : un buzzer passif jouerait la gamme ; le nôtre a fait un clic → **buzzer actif**.
3. **Test 2** : son continu pendant une demi-seconde → le buzzer fonctionne.
4. Pour réécouter : bouton **RESET** de la XIAO (le test est dans `setup()`).

## Pourquoi

- **Deux tests dans le même programme** : on ne savait pas quel type de buzzer contient la mallette ; le résultat des deux tests le dit sans démonter le module.
- **Test dans `setup()`, `loop()` vide** : le son ne se joue qu'une fois au démarrage, au lieu de sonner en boucle.
- **`delay()` accepté ici** : le programme de test ne fait rien d'autre. Dans le jeu, on lancera le son et on n'attendra pas : avec un buzzer actif, `digitalWrite(HIGH)` puis `LOW` quelques dizaines de ms plus tard, mesurées avec `millis()`.
- **Buzzer actif = une seule note** : pour le jeu, on pourra faire des bips (durées différentes), mais pas de mélodie.
